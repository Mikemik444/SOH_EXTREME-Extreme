0.11.59 - Malformed graphics frame and vertex bounds protection (2026-10-02)
  - The 17:11 Jabu-Jabu crash in the supplied log resolves against the saved
    .55 symbols to GfxSpModifyVertex. The register value is vertex index
    0x4DFF (19,967), beyond the 64 normal vertex slots. An unknown opcode
    was logged immediately beforehand. This is an access violation, not
    evidence that receipt history exhausted memory.
  - Release builds now validate vertex load ranges, vertex modifications,
    triangle indices and conditional-branch vertex indices before access.
    Rectangle rendering retains its four reserved scratch vertices. Range
    validation handles unsigned underflow/overflow and null load sources.
  - Unknown opcodes, invalid microcode and rejected vertex operations stop
    the affected frame. No subsequent commands from that frame are executed.
    Valid queued geometry is flushed before restoring the normal framebuffer;
    display-list state is cleared and the next frame starts normally.
  - Diagnostics record raw command words, microcode and bounded caller
    addresses. Repeated errors are rate limited, with no accumulating queue.
    Unrelated exceptions are not swallowed. The malformed-command producer
    is still unidentified; this protects the demonstrated failure path.
  - A controlled protected-page test reproduces the old access violation.
    185,922 assertions pass for the new guard and actual frame/dispatch code.
    Build-time patch tests cover idempotence and atomic rejection of changed
    or ambiguous source. Windows Release build is verified separately.
    No live game/GPU playtest. Existing saves, IDs and placements are unchanged.

VALIDATION LIMITS
Passing generation establishes consistency under the encoded rules. It cannot
prove those rules capture every physical obstacle in the game. No connected
in-game playthrough has been performed by these automated checks, and not every
settings combination is certified. Continue recording concrete counterexamples
like the screenshots, then test both missing-item cases and valid alternatives.
